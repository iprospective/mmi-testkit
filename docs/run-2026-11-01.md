## Constats

1. **`Facture::createFromOrder()` retourne -1** alors que la facture partielle est créée
   (id non nul). Le workflow bascule sur une création manuelle (avertissement, pas échec).
   Cause probable : copie des extrafields/liaisons de la commande vers la facture,
   avec des champs absents côté facture. À qualifier et corriger (cœur ou module).
2. **`pdf_sponge.modules.php` incompatible PHP 8.1** : `round()` reçoit une chaîne
   (`pdf_getlinetotalexcltax`). Ligne 886. Correctif testé dans l’env 20 :
   `round((float) ...)`. À porter dans le fork / proposer upstream.
3. **Incohérence d’extrafields** : `expe_ok` (commande), `palier` et `fk_product_lot`
   (ligne de commande) ne sont pas définis sur la facture / ligne de facture.
   La conversion copie ces champs et échoue. Contournement appliqué dans les bases de
   test (`expe_ok` sur `facture`, `palier`/`fk_product_lot` sur `facturedet`).
   Correctif durable : filtrer les extrafields dans `createFromOrder` ou les déclarer
   côté cible dans les modules concernés.
4. Le paiement doit appeler `Paiement::create($user, 1)` pour clôturer la facture
   (`paye=1`) ; avec `0`, le paiement est enregistré mais la facture reste impayée.

   expédition ; garde ajoutée dans l’env de test, à porter dans le module.
6. **Stock** : `STOCK_CALCULATE_ON_SHIPMENT` et `STOCK_MUST_BE_ENOUGH_FOR_SHIPMENT`
   doivent être activés pour exercer la décrémentation ; l’entrepôt doit être `statut=1`.

   commitent en interne. Les workflows utilisent des références uniques ou des deltas
   de stock ; une remise à zéro de la base reste nécessaire pour des runs parfaitement
   reproductibles.
